# Input Core 真实硬件终验

自动验收只注入已规范化事件，不能替代本清单。未完成本清单时，Input Core 证据必须保持 `hardwareTerminalStatus=not-run` 与 `releaseEligible=false`。

手柄专项现场验收当前未执行，状态保持 `not-run`；未取得真实设备记录前不得声称硬件通过或具备发布资格。范围为 Xbox 布局，优先使用第三方 Xbox 布局手柄的 2.4GHz 接收器；USB 与蓝牙连接可作为补充记录，不扩展为其他品牌布局支持。

## 手柄：第三方 Xbox 布局 2.4GHz 实测

1. 记录 Windows 版本、应用提交、手柄型号、2.4GHz 接收器与连接方式、身份置信度、校准布局/配置 revision，以及测试前后状态。先确认手柄专属授权开启；关闭手柄统计后应停止新增计数。
2. 对每个已校准位置分别实测 A/B/X/Y、D-pad 四向、LT/RT、LB/RB、View/Menu、L3/R3；每项至少操作并释放 10 次，逐项比较实按数、界面统计数和设备/按键归属。跳过或未支持的键须单独标注。
3. 单独验证 D-pad 的 HID hat 数值 0、四向及斜向状态：先记录该型号 hat=0 的实际方向含义，再对每种输入记录应计与实计的方向键数；斜向若产生两个方向计数须如实记录，按当前映射校准无法表达的组合标为未覆盖。
4. 在运行中暂停采集、恢复，再断开并重连接收器；确认暂停期间不增长、恢复后设备可重新出现且不串到另一设备。退出并重启应用，确认授权、所选设备和已保存配置按预期恢复，之后新增计数仍正确。
5. 对选定手柄和完整统计日期执行删除预览及确认，核对预计按键总数、执行前自动备份与删除结果；从该备份恢复后核对逐物理按键计数。另确认该操作不删除其他手柄、键盘或鼠标数据。
6. 将逐键预期/实际次数、hat 原始/映射状态、连接与生命周期结果、删除前后/恢复后计数及证据路径写入记录。USB/蓝牙如测，分别记录连接方式与结果；未测项目保持 `not-run`，不得填通过。

## 两键盘两鼠标与前后台

1. 记录 Windows 版本、应用提交、CPU、内存、四个设备的接口标识、硬件摘要与身份置信度。
2. 接入两套键盘和两套鼠标；每台设备用不同的物理按键、按钮、滚轮方向和移动区间完成可计数动作。
3. 前台与后台各运行至少两轮 30 分钟，共连续不少于 2 小时；后台轮由其他应用获得焦点。
4. 每轮记录各设备预期/实际计数、`produced/accepted/dequeued/sinkAcknowledged`、队列峰值、`overflow/parseErrors/outOfOrder`，逐设备确认零串线。
5. 分别拔出再插入每台设备，记录 arrival generation、接口标识和身份置信度。无法稳定识别时必须标为“需确认”，不得合并历史。
6. 验证 User 暂停后再锁屏/解锁，解锁不得恢复采集；仅移除最后一个暂停原因才恢复。

## 1000Hz 鼠标 30 分钟

1. 记录鼠标型号、接口标识、1000Hz 依据、采样开始/结束时间，持续时间不少于 1800 秒。
2. 记录平均 CPU、峰值工作集、UI 响应测量方法和最大值；目标分别为不高于 3%、200MB、200ms。
3. 记录 Raw Input 接收和管线诊断中的鼠标消息数及全部诊断计数；不得抽样、静默丢点，不能用五键日聚合次数代替输入管线完整性计数。产品不保存鼠标轨迹。
4. 记录绿色版程序目录的实际磁盘增长及测量方法；未测量时标为 `not-run`，不得填 0。
