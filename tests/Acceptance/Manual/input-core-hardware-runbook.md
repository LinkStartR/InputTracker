# Input Core 真实硬件终验

自动验收只注入已规范化事件，不能替代本清单。未完成本清单时，Input Core 证据必须保持 `hardwareTerminalStatus=not-run` 与 `releaseEligible=false`。

## 两键盘两鼠标与前后台

1. 记录 Windows 版本、应用提交、CPU、内存、四个设备的接口标识、硬件摘要与身份置信度。
2. 接入两套键盘和两套鼠标；每台设备用不同的物理按键、按钮、滚轮方向和移动区间完成可计数动作。
3. 前台与后台各运行至少两轮 30 分钟，共连续不少于 2 小时；后台轮由其他应用获得焦点。
4. 每轮记录各设备预期/实际计数、`produced/accepted/dequeued/sinkAcknowledged`、队列峰值、`overflow/parseErrors/outOfOrder`，逐设备确认零串线。
5. 分别拔出再插入每台设备，记录 arrival generation、接口标识和身份置信度。无法稳定识别时必须标为“需确认”，不得合并历史。
6. 验证 User 暂停后再锁屏/解锁，解锁不得恢复采集；仅移除最后一个暂停原因才恢复。

## 1000Hz 鼠标 30 分钟

1. 记录鼠标型号、接口标识、1000Hz 依据、采样开始/结束时间，持续时间不少于 1800 秒。
2. 记录平均 CPU、峰值工作集、UI 响应测量方法和最大值；目标分别为不高于 3%、200MB、200ms。
3. 记录 Raw Input 接收和管线诊断中的鼠标消息数及全部诊断计数；不得抽样、静默丢点，不能用五键日聚合次数代替输入管线完整性计数。产品不保存鼠标轨迹。
4. 记录绿色版程序目录的实际磁盘增长及测量方法；未测量时标为 `not-run`，不得填 0。
