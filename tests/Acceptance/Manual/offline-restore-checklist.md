# 离线恢复人工验收清单

状态：`not-run`。自动验收通过也不代表真实 WPF、SessionEnding 或用户数据恢复已经通过，`releaseEligible=false`。

## 安全前提

- 只使用完整绿色发布目录的全新可丢弃副本，绝不使用唯一用户目录、现有 `.tools/publish/**/data` 或任何需要保留的数据。
- 先复制完整绿色目录两份并分别命名 A、B；确认两个副本均可随时整体丢弃。
- 所选 `.itbackup` 必须位于正在测试的程序目录内；不要使用网络盘、junction、符号链接或程序目录外文件。
- 本清单开始后由人手动操作。自动代理不得替代点击确认、真实重启或结果判断。

## 正向流程

1. 在副本 A 中采集一组可辨认的键盘统计与鼠标按键次数，暂停采集并创建 `backups/state-a.itbackup`。
2. 恢复采集并生成不同的状态 B，再次暂停；记录恢复前的键盘统计、鼠标按键次数、设备筛选与备份哈希。
3. 在界面选择程序目录内 `state-a.itbackup`，核对第一次选择提示，再执行第二次明确确认。
4. 确认恢复期间状态显示“正在停止/恢复”，采集与数据工具不可继续操作；进程随后终止且没有自动重启或恢复采集。
5. 手动重启同一副本，核对键盘次数/按住时长、逐设备鼠标按键次数与设备筛选精确等于状态 A。
6. 记录界面显示的 automatic pre-restore backup 路径；将该备份复制进副本 B 的程序目录。
7. 在副本 B 中按同样的暂停和二次确认流程恢复 automatic backup，进程终止后手动重启，核对结果精确等于状态 B。

## 反向与终止检查

- 未按“用户暂停”、Storage 仍接收写入、未进行第二次确认时，恢复入口必须不可执行，采集不得被停止。
- 程序目录外、绝对路径、非 `.itbackup`、junction/reparse 路径必须拒绝，外部目录无新增文件。
- 恢复成功或失败后均不得自动 resume、重新打开 Storage 或继续采集；shutdown 只发生一次。
- 若出现 `restore-journal.json`，停止人工操作，保留该可丢弃副本用于复现；不要复制到唯一用户目录。
